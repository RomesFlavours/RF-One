Configuration

All Tips settings in one page: first the Distribution Rules (who shares tips with whom, and how much), then the General Configuration (review and validation modes, calculation and payment schedules). Changes here affect the calculations made from then on; Saved Periods already saved keep their own figures.

Distribution Rules

Describe the Tip Distribution Rule
Write the rule in plain language in Your instruction (who gives, who receives, what share, from when) and press Interpret. RF-One asks a question only if something needs clarifying (answer it and press Answer), or tells you plainly when the rule is something it cannot configure yet, keeping what you asked for so you can restate it. Nothing is saved at this stage.
I understood · Confirm / Cancel / Change
RF-One shows what it understood, with any warnings; View structured rule shows the exact fields (source role, recipient role, rate, calculation base, effective dates). Confirm saves the rule (Created by is optional). Cancel discards the proposal and nothing is created. Or describe what to change + Change asks RF-One to revise the proposal. If interpretation is unavailable, a message says so and you can use the Advanced form.
Existing Rules
Each rule with its source and recipient role, calculation base, rate, effective dates, state (ACTIVE or INACTIVE) and number of versions. View / Edit / History opens the rule. Deactivate / Activate switches the rule off or on at once; it can be switched back at any time. Only active rules are used in calculations.
Advanced / Inspect Rule
A direct form to create a rule field by field: Source Role, Recipient Role, Calculation Base, Rate (%), Effective From and, optionally, Created by. Create Rule saves it. A restaurant may have several rules, and one source role may share with more than one recipient role. Manage Roles opens the list of roles the rules can use; if no role exists yet, add one first.

General Configuration

Review Mode
AUDIT: after a calculation you are prompted to check each Host in Explain / Audit Host Tips before relying on the result. AUTOMATIC: no such prompt. It never changes the figures. Set Review Mode saves the choice.
Tips Validation Mode
MANUAL (the default): a person signed in to RF-One must validate each Saved Period before it becomes final. AUTOMATIC: a period becomes final by itself as soon as it adds up, with nobody named as approver. This decides who is accountable for the money, so choose it with care. Set Validation Mode saves it and records who made the change.
Calculation Schedule
When tips are calculated: MANUAL, or AUTOMATIC every N days at an execution time from an anchor date. Update Calculation Schedule saves a new schedule (Set by is optional). Run Calculation Now calculates the latest business date at once and saves its tip entitlements, which are what Payment Control pays; it runs only when the Clover data for that date is ready, and is disabled when that date is already calculated. The note next to the button shows the date and its state.
Payment Schedule
When tips are paid: MANUAL, or AUTOMATIC every N days at an execution time from an anchor date. With AUTOMATIC you also choose the approval: WITH_APPROVAL (a person still approves and pays each cycle) or WITHOUT_APPROVAL (RF-One approves and pays by itself once ready, only if the restaurant has explicitly granted that authority). Payment connector chooses which connector executes the payments (Mercury is currently the only one) and Mercury source account id the account that funds them. Without a connector, Approve & Pay refuses with a clear message. Update Payment Schedule saves it.

Next steps

After changing rules, recalculate the period in Calculate Tips to see their effect. Payment cycles are started and approved in Payment Control.

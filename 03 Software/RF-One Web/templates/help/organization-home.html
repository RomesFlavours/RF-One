How Organization works

Organization describes who is responsible for what in the company. It records the Positions (stable responsibilities such as a manager role), who occupies each one, who covers it when the occupant is away, and which Position owns each business Process. RF-One uses this to decide who should receive an Attention Item: a request for a person's attention raised by a Process. These pages are for configuration, inspection and testing; they are not the place where people receive or handle their everyday requests.

How it works

  • A Position is a responsibility, independent of the person in it. Positions report to a parent Position, forming the chart. A Position without an occupant is shown as VACANT, which is a normal state.
  • A Position's Scope says where it applies (for example a Restaurant, a Location, a Legal Entity or a Domain). A Position with no Scope applies everywhere.
  • Process Ownership says which Position is responsible for a Process, or for one phase of it.
  • When a Process raises an Attention Item, RF-One finds the owning Position and looks for the recipient in this order: the delegate of an active Temporary Coverage of that Position (for example during holidays), otherwise its current occupant; then its Backup Positions, in their order; finally the Position named by the Organizational Fallback Policy. If nobody can be found the item stays unresolved; RF-One never guesses a recipient.

Typical flow

  1. Create the Positions and their reporting lines{% if may_use_item('ORGANIZATION', 'positions') %} in Positions{% endif %}.
  2. For each Position, set its Scope, assign the occupant and add Backup Positions.
  3. Record which Position owns each Process{% if may_use_item('ORGANIZATION', 'process_ownerships') %} in Process Ownerships{% endif %}.
  4. Set a company-wide fallback Position{% if may_use_item('ORGANIZATION', 'fallback_policies') %} in Organizational Fallback Policy{% endif %}, used only when nothing else resolves.
  5. Check the result with the coverage counts on this page{% if may_use_item('ORGANIZATION', 'coverage_check') %} and in Full Coverage Check{% endif %}, and fix the gaps.
    6. {% if may_use_item('ORGANIZATION', 'attention') %}
  6. Inspect the Attention Items and how each was routed in Attention Items.
    7. {% endif %}

What this page shows

Section buttons
One button for each Organization section your account may use.{% if may_use_item('ORGANIZATION', 'positions') %} Positions: list and edit the Positions.{% endif %}{% if may_use_item('ORGANIZATION', 'process_ownerships') %} Process Ownerships: which Position owns which Process.{% endif %}{% if may_use_item('ORGANIZATION', 'fallback_policies') %} Organizational Fallback Policy: the last-resort recipient.{% endif %}{% if may_use_item('ORGANIZATION', 'coverage_check') %} Full Coverage Check: the per-Process detail of the counts below.{% endif %}{% if may_use_item('ORGANIZATION', 'attention') %} Attention Items: inspect requests and their routing.{% endif %}{% if may_use_item('ORGANIZATION', 'interviews') %} Interviews · TEST: the test area for interviews.{% endif %}{% if may_use_item('ORGANIZATION', 'ai_review') %} AI Consistency Review (boundary): shows what a future automatic review would receive; no review runs yet.{% endif %}
Organizational Coverage
Live counts answering "if a Process raised an Attention Item now, would someone receive it?": Processes known; Fully covered (the owner's occupant or an active Temporary Coverage receives it); Partial coverage (Backup/Fallback); Configuration gap (undelivered) (nobody would receive it); Fallback used; Missing required Backup (Positions marked as requiring a Backup Position that have none); Unresolved Attention Items.
Organizational Health
A separate question: is a primary owner correctly configured for each Process? Primary ownership configured, No owner configured and Ambiguous ownership (more than one equally valid owner). A Process can be delivered through a Backup or the Fallback and still have no primary owner; both are shown.
Organization Chart
The Positions drawn from the current data, each under the Position it reports to. Each box shows the Position's name, its occupant (or VACANT) and its Scope, and, when they apply, its Backup Positions, who is covering it, and warnings such as Configuration gap, Covered via Backup, Covered via Organizational Fallback or Backup required, none set. A greyed box is an inactive Position.

Process Ownerships

A Process Ownership says: "this Position is responsible for this Process (or one phase of it) in this Scope". RF-One uses it to find who should receive the Attention Items that Process raises. This page lists every ownership{% if org_may_administer() %} and lets you add new ones{% endif %}.

Columns

Domain / Module / Process
The Process, named by the Domain and optionally the Module it belongs to.
Phase
One phase of the Process (PLANNING, SCHEDULING_PROGRAMMING, MANAGEMENT or OPERATIONS), or (whole process).
Position
The owning Position{% if may_use_item('ORGANIZATION', 'positions') %}; click it to open the Position{% endif %}.
Scope override
A Scope that applies to this ownership only; (uses Position's own scope) when none is set.
{% if org_may_administer() %}

New Process Ownership

Domain
Required. The name of the Domain the Process belongs to, typed as text.
Module
Optional module name.
Process name
Required. It must match the name the Process uses when it raises Attention Items, otherwise those items will not find this owner.
Phase
Optional: choose a phase, or leave (whole process).
Owning Position
The Position responsible.
Scope override (optional), scope_id, scope_key
Leave the override empty to use the Position's own Scope. If you choose a type, give its value: a number in scope_id for types identified by a number (for example a Restaurant or Legal Entity), or text in scope_key for types identified by a name (Domain, Module, Process, Process Phase). GLOBAL needs no value.

Buttons and what happens

Create Process Ownership
Adds the ownership and reloads the page. If a required field is missing or the scope value does not fit its type, nothing is saved and the reason is shown. Ownerships cannot be edited or removed from this page. If two ownerships end up equally valid for the same Process, the Coverage Check reports the ownership as ambiguous.

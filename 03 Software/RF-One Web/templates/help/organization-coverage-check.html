Organizational Coverage Check

This page answers, for every Process RF-One knows about: "if this Process raised an Attention Item right now, would someone actually receive it?". It is computed live each time you open the page, from the Process Ownerships, the Attention Items already raised, and the occupants, Temporary Coverage, Backup Positions and Fallback Policy. It only reads: nothing is changed here.

The counts

Delivery
Processes known (every Process with an ownership or with an Attention Item already raised); Fully covered (the owner's occupant, or the delegate of its active Temporary Coverage, would receive it); Covered via Backup; Covered via Organizational Fallback; Gap (undelivered): nobody would receive it.
Organizational Health
A separate question: is a primary owner correctly configured? Primary ownership configured, No owner, Ambiguous owner (more than one equally valid owner). A Process can be delivered through the Fallback and still have no owner; both facts are always shown.

Tables

Per-Process detail
One row per Process and phase: Delivery (FULLY_COVERED, COVERED_VIA_BACKUP, COVERED_VIA_FALLBACK or GAP), Ownership health (CONFIGURED, NO_OWNER or AMBIGUOUS_OWNER), the Owner Position (click to open it) and a Detail saying who would receive the request and how, or why nobody would.
Positions requiring a Backup but missing one
Positions marked as requiring at least one active Backup Position that have none.
Unresolved Attention Items
Items already raised for which routing found no recipient, with their priority, source and the reason. Click the reason to open the item.

Next steps

For a GAP or NO_OWNER, add a Process Ownership; for a vacant owner, assign an occupant, a Temporary Coverage or a Backup Position; as a last resort set the Organizational Fallback Policy. These changes are made by the administrators of the Organization Domain. Then reopen this page to see the new result.

How Wines works

Build a reliable catalog, prepare a Wine list for each Entity, and control its selling prices and effective dates.

Workflow · Catalog and types · Pricing · Price Calculator · Versions · Access · Wines agent features

The workflow

  1. Define Wine Types. Create a standard name and alternative names so the same type is recognized consistently.
  2. Maintain Availability. Record the wines you can buy, their suppliers, costs and availability.
  3. Select the Entity. Each Entity has its own dated Wine list versions.
  4. Create a New Wine list. Choose an effective date and start empty or copy the list currently in effect.
  5. Add wines and set prices. Choose catalog wines, enter their commercial Value, and decide whether they are sold by the glass. Review calculated prices or set them manually.
  6. Review and export. Check incomplete prices and change warnings, then export the selected version as CSV. A future version becomes effective on its date.

Wine Types and Availability

Wine Types stores a standard name and alternative names. Names already assigned to another type are refused.

Availability is the purchasing catalog, not an inventory count. A wine records its type, producer, label, vintage or non-vintage status, category, style, denomination, region, bottle size, supplier, cost, cost date and notes. Availability can be Available, Incoming or Not available.

Search the catalog to find an existing wine before adding one. Duplicate wine identities are rejected. An unknown cost can stay blank; it is never silently treated as zero.

Pricing and manual decisions

The calculator follows the Wine workbook. With cost C, commercial Value V and parameters A, B and G, the multiplier is A / logB(C). The bottle price is C × multiplier × V²; the glass price is that unrounded amount divided by G. Each price is rounded independently to whole dollars, with halves rounded up.

Value is your commercial assessment, not an AI rating. G is a commercial divisor. The initial parameters are A = 1.3, B = 900 and G = 3.5; Pricing parameters lets you change them. A missing cost or cost of $1 or less cannot produce a calculated price.

You can override bottle and glass prices manually and restore calculated prices later. The list shows which prices were set by hand. Catalog cost changes and parameter changes are flagged; existing list prices do not change silently. Use the explicit adoption and recalculation actions after reviewing the change.

Price Calculator

The Price Calculator tab answers a quick question: what would this wine sell for? Enter the bottle cost and its commercial Value (it starts at 1.0 and is shown with one decimal; the arrows, or the mouse wheel while the field is selected, change it by 0.1); the bottle and glass prices appear as you type.

It uses the same formula and the pricing parameters in effect shown under Pricing parameters, so its prices match what a Wine list would calculate for the same cost and Value. Nothing is saved: closing or leaving the page keeps no trace. A cost of $1 or less has no calculated price.

Wine list versions and effective dates

Versions are maintained separately for each Entity. The effective date determines whether a version is In effect, Prepared (future) or Previous. Preparing a future version leaves today's list in effect until the new date.

Copying the current list preserves its selected wines, costs used, commercial Values, calculation parameters and prices. Previous versions remain available for consultation and export, and cannot be edited. Dates follow the restaurant Location's timezone.

Who can do what

Wines has two functions that can be granted separately, to a role or directly to a person: Wines (Wine List, Availability, Wine Types, Pricing parameters and Export) and View Calculator (the Price Calculator). You only see the tabs of the functions you were given; Whole domain gives both.

The Level View lets you consult everything your functions open — lists, catalog, types, parameters and exports — without changing anything: the buttons to add, edit, delete, create lists or save parameters are not shown, and changes are refused. User and Domain administrator can change everything. When several roles give you Wines, the highest Level applies.

Wines agent features

The current Wines implementation provides structured operational assistance: consistent wine identities, duplicate checks, cost and price validation, deterministic price calculations, per-Entity list versions, change warnings and CSV export.

You supply and approve supplier information, availability, costs, commercial Value, selling prices and effective dates. The current module does not connect to a generative AI model, research suppliers, place orders, track physical stock or autonomously publish recommendations. These are not active features of this installation.

Primary Screening Criteria

Screening Criteria are the restaurant's own rules for the first, quick screening of Applications, before any interview. Every Criterion uses the same 0-4 level scale, but what each level means, how important the Criterion is, whether it counts for or against, and whether it can exclude an Application (Hard Disqualifier) are the restaurant's choices. The first time the page opens, RF-One adds a set of starter Criteria, which you can edit or deactivate.

How it works

  • When Primary Screening runs on an Application, every active Criterion for its role (or for every role) is copied as it is at that moment, so later edits never change a screening already done.
  • Each Criterion is evaluated first from its linked Signal, if one is configured; otherwise RF-One asks its AI assistant to propose a level from the evidence already in the Application, using only the level meanings written here. If no AI service is available, or the evidence is insufficient, the Criterion stays unresolved for the Selezionatore. A level is never invented.
  • Evaluated levels, multiplied by the coefficient and signed by the direction, determine the order of the screening queue. An Application reaching a Hard Disqualifier's trigger level (or higher) goes to the separate Hard Disqualifier pool until a Selezionatore overrides it.

Fields and columns

Card badges
Direction, coefficient, "HARD DISQUALIFIER @ level N", target role, INACTIVE and version.
Name / Description / Category (free text)
What the Criterion is about.
Target role (leave blank to apply to every role) / Location/context
Limits the Criterion to one role; the location is descriptive.
Coefficient
How important the Criterion is (default 1.0).
Direction
POSITIVE (a higher level helps) or NEGATIVE (a higher level counts against).
Hard Disqualifier / Hard Disqualifier trigger level (0-4)
When ticked, an evaluated level equal to or above the trigger level moves the Application to the Hard Disqualifier pool. It is never deleted.
Level meanings (0-4)
What each level means for this Criterion, in the restaurant's own words. Both people and the AI assistant choose among these meanings.
Allowed evidence sources
Which evidence may be used (résumé facts, application, application history, Fit Assessment, Selection Signal, consistency information, Selezionatore input, other).
Evaluation / Positive / Contrary / Insufficient evidence guidance
Instructions for whoever evaluates the Criterion.
Optional: auto-evaluate from an existing Selection Signal / Signal status → level mapping
Links the Criterion to a Signal and says which level each Signal status gives (for example DETECTED → 4). Leave a status unmapped to skip it.

Buttons and what happens

Create Criterion
Saves a new active Criterion; it is used by screenings run from now on. A name is required.
Edit this Criterion → Save Criterion
Saves all fields as shown and increases the version. Existing screenings keep the version they used; use "Re-run Primary Screening" on an Application to apply the new rules to it.
Deactivate / Reactivate
Stops or resumes using the Criterion in new screenings. Reactivation is refused (the page reloads unchanged) while its latest Compliance Review has an unresolved HIGH CONCERN.
Compliance Review → Run Compliance Review
Checks the Criterion's text automatically for wording about personal characteristics, vague wording, characteristics hard to judge at this stage, or missing information treated as negative, and stores the result. It is an aid, not legal advice.
Record Decision
Stores your response to the latest review (Accept Rewrite, Edit Manually, Keep Original, Deactivate, Acknowledge High Concern) under your acting identity; the "Your name" field is not used. A reason is required for Acknowledge High Concern, and for Keep Original against a High Concern. The decision does not change the Criterion's text or status by itself; Accept Rewrite, Edit Manually and Acknowledge High Concern lift the block on reactivation.

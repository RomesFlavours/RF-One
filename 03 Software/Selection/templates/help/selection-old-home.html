How Selection Old works

Selection Old is the historical Selection interface, kept available next to the current one. It screens résumés and organizes structured evidence to support the person who evaluates candidates. It never takes a hiring decision, never rejects anyone automatically and never shows a universal résumé score.

How it works

  • Each imported résumé becomes a candidate (the data read from the résumé) and an application for the target role you choose at import. The same person can hold several applications, for different roles or at different times.
  • The candidate page separates facts read from the résumé, derived information calculated from them, flags worth asking about and separate indicators; none is combined into a score.
  • Applications are reviewed in the Applications queue, where a Review Priority suggests where to look first. Workflow status, stage and outcome are always set by a person.
  • The menu at the top leads to the configuration areas (requirement sets, screening criteria, signals, priority policies, interview questions and sections, outcomes, queues, sources, channels, templates, reminders) and to the other review lists. Each page has its own "How this page works".
  • Messages to candidates are recorded with their status, but in this version Selection Old has no real SMS or e-mail provider connected: no message actually reaches the candidate.

Typical flow

  1. On this page, choose the target role and import one or more résumés.
  2. Open a candidate to check what was read from the résumé, against the original, and create a Fit Assessment against a requirement set.
  3. In Applications, filter the review queue, compare applications of the same role and open one to review it.
  4. On the application page, set the workflow status, run Primary Screening, create phone or in-person interview plans and resolve possible identity matches.
  5. In the Candidate Dossier and the Decision Summary, take the application in charge, move its stage, apply an outcome and keep notes. The Audit page shows the whole journey for review.

Target role for these applications
Required, with no default: the one choice applies to every résumé of the batch. Without it nothing is imported.
Candidates table
Name, location, source, current or latest role, number of employment records, target role, months of direct experience ("to be clarified" when unknown), stability, number of flags, information confidence, status and how the résumé was read: REAL AI, RULE-BASED (the built-in text reader, used when no AI provider is configured) or DEMO / MOCK. Click a row to open the candidate.

Buttons and what happens

Import Résumés
Processes each file separately, so one failed file does not stop the others, and shows each one's result: COMPLETED, PARTIAL (read only in part), DUPLICATE (already imported, skipped) or FAILED. If the same résumé was already imported for another role, a new application is created for this role. Each imported résumé creates a candidate and an application. When the batch ends the list refreshes by itself (or use Refresh candidate list).

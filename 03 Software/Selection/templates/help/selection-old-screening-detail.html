Primary Screening of an Application

This page shows one Primary Screening run for one Application: the result, the evaluation of each Screening Criterion with the evidence used, and the controls to confirm, enter, override or annotate each evaluation. It always shows the most recent run; earlier runs stay tied to the Criteria as they were when those runs were created.

Each Criterion Evaluation

Badges
Direction, status (EVALUATED, INSUFFICIENT EVIDENCE, NOT APPLICABLE, NOT EVALUATED), origin (for example system generated or human overridden) and Hard Disqualifier state.
Level
The current level and its meaning; "(system-proposed level was N)" appears when a person changed it. The system proposal is always kept.
Confidence / Evidence used / explanation
How sure the evaluation is, the evidence it relies on (source, text, interpretation) and why the level was chosen.

Buttons and what happens

Re-run Primary Screening (uses current Criteria configuration)
Creates a new run against the Criteria as they are now (Signal mapping first, then RF-One's AI assistant when available) and opens it. The previous run is kept, not overwritten.
Add note (run, or "Notes on this Criterion Evaluation")
Saves a dated note on the whole run or on one Criterion. Notes cannot be edited or deleted.
Enter / change level → Save (entered by Selezionatore)
Records the level you choose, with optional confidence, evidence source, evidence text and explanation, and recalculates the run.
Override level → Override
Shown on evaluated Criteria. Replaces the level with yours, records your reason and recalculates the run; the system level stays visible. For an Application in a Selection Session, only the person who has taken it in charge (or someone with authority over them), in a Session whose Rule Set is confirmed, can override.
Confirm current level
Records that a person has checked and accepted the current level.
Mark Not Applicable / Mark Insufficient Evidence
Sets the Criterion to that status; it then no longer contributes to the order of the queue. Insufficient Evidence counts as "unresolved" in the queue. A missing piece of information is never treated as a negative result.
Override this Hard Disqualifier → Override Hard Disqualifier
Requires a reason. Returns the Application to the normal pool, while the Hard Disqualifier, its level and evidence stay visible with your reason. The same ownership rule as "Override level" applies. Good to know

When an action is refused (for example an override by someone who has not taken the Application in charge, or a Hard Disqualifier override without a reason), the page reloads unchanged without an error message.

Next steps

Selection Session

This page manages one Selection Session: its status, its Job Postings, the Selezionatori assigned to it, its Rule Set (the rules every Application in the Session is worked under), rule changes, its Applications, interview scheduling windows and notes.

Typical flow

  1. Check the Rule Set and, if needed, edit it with Edit Rule Set (before confirmation).
  2. Assign one or more Selezionatori.
  3. Confirm the Rule Set: the Session becomes ACTIVE and its Applications can be worked.
  4. Link Applications, generate a Job Posting draft and offer scheduling windows.
  5. If a rule must change while the Session is ACTIVE, propose a Rule Change and confirm the new version.

Session header

Role / Branch / Location / Start date
The details of the hiring need.
Rule Set
The current version and whether it is Confirmed. While it is "Not confirmed", a note warns that operational work on the Session's Applications (Take In Charge, Outcome or Stage changes, screening and Trainable Gap edits) is blocked.
Change Session status → Save status
Sets DRAFT, RULES REVIEW, ACTIVE, PAUSED or CLOSED. Closing records the closing date. Applications can be worked only while the Session is ACTIVE and its current Rule Set is confirmed.

Job Postings

Open →
Opens a Job Posting generated for this Session.
Generate Draft
Creates a plain, generic Job Posting draft from the Session's role and context (never from internal screening criteria, never with invented pay or benefits) and opens it for review. It is never published automatically. The name field is stored as typed.

Assigned Selezionatori

Assign a Selezionatore → Assign
Adds a registered person to the Session, optionally with an authority level. Without a level, assigned people are peers: none can reassign an Application another one has taken in charge.{% if not rfone_login_mode %} If the person is not listed, use "Register a new Acting Identity" first.{% endif %}
Deactivate
Ends that person's assignment to the Session; the history is kept.

Rule Set — Review

Requirements / Selection Signals / Primary Screening Criteria / Outcome Definitions referenced
What the current version contains: the Requirement Set with each requirement's criticality and trainability, the Signals, the screening criteria (direction, coefficient, Hard Disqualifier, level meanings) and the Outcomes.
Edit Rule Set (before confirmation) → Save Rule Set (new version)
Available only while the Rule Set is not confirmed. Saves a new version with the selected Requirement Set, criteria, Signals and Outcomes. Only the Requirement Set is pre-selected: in the three lists, select again everything you want to keep (Ctrl/Cmd-click for several), because whatever is not selected is left out of the new version.
Confirm Rule Set → Confirm Rule Set & Activate Session
Confirms the current version under your acting identity{% if not rfone_login_mode %} (use "not you?" to switch identity first){% endif %}, with an optional note, and makes the Session ACTIVE. A confirmed version cannot be edited: further changes go through a Rule Change. If your role is not allowed to confirm, the page reloads without changes.
{% if selection_session is defined and selection_session.status == 'ACTIVE' %}

Propose a Rule Change

Shown only while the Session is ACTIVE. Enter what changed and a mandatory reason, then choose the scope: Subsequent Applications Only, or Entire Session, which also lists the Applications already processed so they can be recalculated where possible and reviewed. Leave the Requirement Set and criteria empty to carry them forward unchanged. Propose Rule Change creates a new, unconfirmed Rule Set version: the Session needs a new confirmation before work can continue. The change is recorded in the Rule Change History and in the Session notes.

{% endif %}

Applications needing review after a Rule Change

When shown, lists the Applications affected by an "Entire Session" change, with their recalculation and review status. Mark reviewed records that you have checked one; it does not change the Application.

Applications

Candidate / Applied / Owner / Rule Set version
Each linked Application, who has taken it in charge ("(unclaimed)" if nobody) and the Rule Set version it was worked under. Open Dossier → opens the Application's Dossier.
Link an existing Application to this Session → Link to Session
Links an Application for the same role that is not yet in any Session. An Application already in another Session cannot be moved.

Interview Scheduling Windows

A window is offered once for the whole Session and interview stage (Phone Interview or In Person Practical) and is shared by every eligible Application: once a slot is fully booked, it is no longer offered to anyone else. Offer a new scheduling window → Add Scheduling Window saves the date, start and end time, slot length (minutes, default 30) and capacity per slot (default 1). Candidates then book a slot through their scheduling link.

Session Notes

Add Note saves a general note on the Session. Notes cannot be edited or deleted; RF-One also adds notes automatically for confirmations and rule changes.

Good to know

When an action is not allowed (for example a missing reason, or a Rule Change on a Session that is not ACTIVE), the page simply reloads unchanged, without an error message.

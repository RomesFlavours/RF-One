Signals

A Selection Signal is something worth noticing about an Application (for example "Recent relevant experience" or "Long gap in relevant work"). This page holds the restaurant's Signal Definitions: what each Signal means, at which stages it can be judged and from which evidence. How much a Signal changes an Application's Review Priority is set separately, on Priority Policies.

How it works

  • The definitions are grouped by family: Fit Experience, Readiness Recency, Motivation Personal, Motivation Professional.
  • When the stages include RESUME and the definition has a Subtype that matches one of RF-One's built-in detectors (recent_relevant_experience, long_relevant_gap, progression_since_previous_application, explicit_interest_statement, fit_assessment_strength), RF-One checks résumé facts automatically and records the Signal on each Application as Detected, Possible, Conflicting or Not Detected. Without a matching subtype, the Signal is assessed by people (for example from interview answers).
  • Detectors look only at professional facts (dates, roles, certifications, explicit résumé text); they never infer personal reasons.

Fields and columns

Card
Name, subtype, INACTIVE when switched off, version (for example v3), description, the stages where it can be assessed, the allowed evidence sources and the evidence guidance.
Name / Signal family
The Signal's label and its group. Both are required.
Subtype (optional …)
The code of a built-in detector (see above). Leave blank if the Signal is only assessed manually.
Description
What the Signal means and why it matters to the restaurant.
Applicable assessment stage(s)
Where it can be judged: RESUME, PHONE INTERVIEW, IN PERSON INTERVIEW, PRACTICAL ASSESSMENT, REFERENCE CHECK, OTHER.
Allowed evidence source(s)
Which kinds of evidence may support it (résumé fact, phone answer, in-person observation…).
Detection guidance / Supporting / Contrary / Insufficient evidence guidance
Written guidance for the people assessing the Signal: how to recognise it, what supports it, what goes against it and what is not enough to conclude.

Buttons and what happens

Create Signal Definition
Saves a new active definition. If the name or family is missing, nothing is saved.
Edit this Signal Definition → Save Signal Definition
Saves the changes and increases the version. Signals already recorded on Applications are not recalculated by saving; new checks use the new definition.
Deactivate / Reactivate
Stops or resumes using the definition for new checks. The definition and existing observations are kept.

Next steps

On Priority Policies, decide which Signals (and which observed status) should raise or lower the Review Priority. Signals can also be used to evaluate a Primary Screening Criterion automatically.

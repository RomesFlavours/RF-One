Review Priority Policy

This page shows one Review Priority Policy and its rules. Each rule says how one Selection Signal, observed with one status, contributes to an Application's Review Priority. Contributions are qualitative (from Strongly Increase to Strongly Decrease), never numeric scores.

How the rules produce a priority

  • Only active rules count, and only for Signals observed on the Application. A NEUTRAL contribution counts as nothing.
  • A Strongly Increase, or two or more Increase, with nothing lowering: HIGH PRIORITY. A single Increase alone: INTERESTING.
  • The same on the lowering side: a Strongly Decrease or two or more Decrease give LOW PRIORITY; a single Decrease alone gives INTERESTING.
  • Contributions in both directions: INTERESTING, with the reasons on both sides shown. Nothing contributing: STANDARD.
  • Changes apply the next time an Application's priority is calculated (for example when its Signals are refreshed); priorities already calculated are not changed by saving here, and a Selezionatore's manual override is never replaced.

Fields and columns

Policy / Status
The policy name and whether it is ACTIVE. If several policies are active, RF-One uses the most recently changed one.
Signal Definition
The Signal the rule refers to.
Observed status
The status the Signal must have on the Application: DETECTED, POSSIBLE, CONFLICTING, NOT DETECTED or NOT ASSESSED. The rule counts only when the Signal's current observation on the Application has exactly this status.
Contribution
STRONGLY INCREASE, INCREASE, NEUTRAL, DECREASE or STRONGLY DECREASE.
Status (rule)
ACTIVE rules count; INACTIVE rules are kept for reference only.

Buttons and what happens

Deactivate this policy / Reactivate this policy
Stops or resumes using the policy. With no active policy every newly calculated priority is STANDARD.
Rename policy → Save name
Changes only the name.
Contribution (drop-down in a row)
Saves the new contribution as soon as you choose it.
Deactivate / Reactivate (row)
Keeps the rule but stops (or resumes) counting it.
Remove
Deletes the rule permanently, with no confirmation and no undo. It does not touch the Signal Definition or any Signal already observed. Prefer Deactivate if you may need the rule again.
Add rule
Adds a rule for the chosen Signal Definition, observed status and contribution.

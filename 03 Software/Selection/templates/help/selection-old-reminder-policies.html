Reminder Policies

A Reminder Policy decides what happens when a candidate does not reply to an automatic message of a given kind (for example "Advance To Phone Scheduling"): how many reminders to send, how long to wait before each one, the final deadline for a reply and whether RF-One may then apply a STOP Outcome automatically, with the reason "NO RESPONSE". Without an active policy, a message waits for no reply and nothing follows it.

How it works

  • When a message is sent, RF-One looks for the most specific active policy for its trigger event, the Application's Stage and its role. If one exists, RF-One starts waiting for a reply and sets the final deadline.
  • Each reminder uses the active Communication Template with the trigger "Reminder". If no such template exists, the reminder is counted but no message goes out.
  • If, after all reminders, the final deadline passes with no reply, the chosen Outcome is applied automatically only if "Automatically apply STOP…" was ticked and an Outcome was chosen. Otherwise the Application stays as it is.
  • Changing or deactivating a policy affects messages sent afterwards; a message already waiting keeps the policy it started with.

Fields and columns

Configured Reminder Policies
Each card shows the trigger event, the Stage, the number of reminders and delays, the final deadline and whether Auto-STOP is enabled (and with which Outcome).
Trigger event this governs
The kind of message whose reply is awaited.
Stage / Role (leave blank for any)
Limit the policy to one Stage, typed exactly as the Stage code (for example PHONE_INTERVIEW), and/or one role.
Number of reminders
How many reminders to send before the deadline (an empty value means none).
Delay before Reminder 1 / Delay between reminders (hours)
Waiting time after the original message, and between one reminder and the next.
Final response deadline (hours after original send)
After this time, with all reminders sent and no reply, the no-response rule applies.
Automatically apply STOP … / Outcome to apply automatically
The explicit permission for an automatic STOP, and which Outcome to apply. Both are needed.

Buttons and what happens

Create Policy
Saves the policy as active immediately. This page has no form to edit a policy afterwards: deactivate it and create a new one.
Deactivate / Reactivate
Switches the policy off or on for future messages.

Current limitations

Reminders and automatic stops are not processed on a timer in this version: they happen only when RF-One's reminder processing is run, and this interface has no button for it. As on Communication Templates, no real SMS or e-mail delivery service is connected, so reminders are recorded but do not reach the candidate.

Next steps

Make sure a "Reminder" template exists on Communication Templates, and that the Outcome used for automatic stops is configured on Selection Outcomes.

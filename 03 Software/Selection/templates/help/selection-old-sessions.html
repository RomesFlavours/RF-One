Selection Sessions

A Selection Session is the working container for one hiring need for one role (for example "Server — Winter Park — September 2026"). It groups the Applications for that need, the Selezionatori who work on them and the Rule Set (requirements, screening criteria, Signals and Outcomes) that governs the Session. This page lists every Session and lets you start a new one.

Typical flow of a Session

  1. Create the Session here; it starts as DRAFT and opens automatically.
  2. On the Session page, review and complete its Rule Set, assign the Selezionatori and confirm the Rule Set: the Session becomes ACTIVE.
  3. Link or receive Applications, offer interview scheduling windows and work the Applications.
  4. Pause or close the Session when the need is filled.

Fields and columns

Session name
A clear name for the hiring need. Required.
Role (single role only)
The one role recruited (for example SERVER). Required.
Branch / location (optional)
The branch the need belongs to.
Created by
Your name, stored as typed for reference.
Status
DRAFT, RULES REVIEW, ACTIVE, PAUSED or CLOSED.
Applications / In review (owned)
Applications linked to the Session, and how many of them a Selezionatore has taken in charge.
Rule Set
The current Rule Set version and "confirmed" once it has been confirmed.
Selezionatori
The people currently assigned to the Session.

Buttons and what happens

Create Session
Creates the Session in DRAFT with a first, unconfirmed Rule Set version. When an earlier Session exists for the same role, its current rules are copied as the starting point; otherwise the Rule Set starts empty. Then the new Session's page opens. If the name or role is missing, nothing is created.
Open → (or click a row)
Opens the Session's page.

Next steps

Open the new Session and confirm its Rule Set: until then, operational work on its Applications (taking them in charge, Outcome or Stage changes, screening edits) is blocked.

Selection Outcomes

A Selection Outcome is the operational decision that currently applies to an Application (for example Hire, Hold, Stop, Withdrawn). It is separate from the Stage, which says where the Application is in the process. This page defines the restaurant's Outcomes and what happens each time a Selezionatore chooses one. The first time the page opens, RF-One adds a few common examples (and the default queues); you can edit them or add your own.

How it works

  • A Selezionatore applies an Outcome from an Application's pages; RF-One then applies the settings below (lifecycle change, queue move, follow-up, Candidate Flag) and, if a matching Communication Template exists, sends its message.
  • No Outcome is permanently irreversible: a closed Application can always be reopened.
  • Editing an Outcome increases its version and applies to future decisions; decisions already taken keep the version that was used.

Fields and columns

Card
Name, the lifecycle it leads to (→ ACTIVE, SUSPENDED or CLOSED), INACTIVE when switched off, version, description and a summary of its settings.
What should this Outcome be called? / Describe it …
The name (required) and a plain description of when to choose it.
What should happen to the Application when this Outcome is chosen?
Stays ACTIVE (still being considered), becomes SUSPENDED (paused) or becomes CLOSED (no longer worked).
This Outcome is normally expected to be reopenable later
If unticked, a warning appears when someone reopens it; reopening is never blocked.
Require a Note / Require a reason every time …
The Selezionatore cannot apply the Outcome without writing a note or giving a reason.
Optional: offer a pick-list of reasons (one per line)
Ready-made reasons the Selezionatore can choose from.
Optional: move the Application into this operational queue/list
Moves the Application to the chosen queue (see Selection Queues). A queue is organisational only.
Create a follow-up reminder … / Follow up after how many days?
Creates a reminder on the Application; once due, it appears under "Reminders Due" on the Primary Screening page. RF-One never acts on it by itself.
Should this restaurant contact the candidate again in the future?
Records whether future contact is fine, discouraged or to be avoided.
Create a Candidate Flag … / Flag name / Flag scope / How seriously … / Default reason / Flag expires after how many days?
Adds a note that follows the person to future Applications (for example "RECONSIDER AFTER 6 MONTHS"): its name (default: the Outcome's name), scope, how prominently it is shown (information only, a warning, or requiring Selezionatore attention — never an automatic rejection), a default reason and an optional expiry.
Who normally has authority to apply this Outcome?
Informational only; it does not restrict who can apply it.
Is this Outcome normally restaurant-driven or candidate-driven?
Restaurant, Candidate, Either, or unspecified — informational.

Buttons and what happens

Manage operational queues/lists →
Opens the Selection Queues page.
Create this Outcome
Saves a new active Outcome. If the name is empty, nothing is saved.
Edit this Outcome → Save changes
Saves every field of the form as shown (an unticked box is saved as "no") and increases the version.
Deactivate / Reactivate
Removes the Outcome from (or returns it to) the choices offered for new decisions. Past decisions are kept.

Next steps

To send a message when an Outcome is applied, create a Communication Template naming this Outcome and the Stage. To include the Outcome in a Session's rules, select it in the Session's Rule Set.
